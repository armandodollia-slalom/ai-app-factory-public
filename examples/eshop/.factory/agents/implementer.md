### Stack

AI Immersion eShop: .NET Aspire, a Blazor WebApp and microservices over RabbitMQ. Architecture docs are in `docs/architecture/` (`services.md`, `event-flows.md`, `infrastructure.md`); read the relevant parts before changing code. Stories are GitHub issues on the story board. The pipeline is described in `docs/ai-pipeline/README.md`.

### Shell setup

- `dotnet` is not on PATH: run `export PATH=$HOME/.dotnet:$PATH` in each shell command that needs it.
- The shared test stack runs on Docker Compose; never use it from a worktree.

### Conventions: which example to follow

| Concern | Follow |
| --- | --- |
| New service | An existing API project (`src/Catalog.API`, `src/Webhooks.API`): `Extensions/Extensions.cs` `AddApplicationServices`, `MapDefaultEndpoints`, minimal-API endpoint groups with versioning, `eShop.ServiceDefaults` |
| AppHost wiring | `src/eShop.AppHost/AppHost.cs` — same `AddProject`/`WithReference`/`WaitFor` style as neighbours; new DB via the existing Postgres resource |
| Auth scope | `src/Identity.API/Configuration/Config.cs` API scopes and clients |
| Persistence | EF Core `DbContext` + migrations; seed through `MigrateDbContextExtensions` so the teststack seeder switch still works |
| Domain logic (Ordering) | DDD in `src/Ordering.Domain` — behaviour on aggregates, not in handlers |
| Integration events | `IntegrationEvent` records, publish through the `IntegrationEventLogEF` outbox where the service already uses it; register handlers with `AddSubscription` |
| AI features | `IChatClient` from `AddAIServices`; tools via `AIFunctionFactory.Create` (see `src/WebApp/Components/Chatbot/ChatState.cs`) |
| WebApp UI | `src/WebApp` + `src/WebAppComponents`; pages are static SSR by default — add interactivity only where the story needs it |

A file you may read in full as a template: an existing `Program.cs` for a new service. graphify labels look like `MigrateDbContextExtensions.AddMigration()`.

### Rules

- **Clock:** no hidden statics or `DateTime.Now`; inject `TimeProvider`.
- **Package versions** go in `Directory.Packages.props` (central package management), never in a `.csproj`.
- **Generated files:** `deploy/teststack/*` is regenerated by `factory teststack publish`; don't hand-edit it.
- **API versioning:** services use Asp.Versioning with no default version, so callers pass `?api-version=1.0`. Follow that and note it in the report.
- **EF migrations:** `dotnet-ef` isn't installed. Install it into your scratchpad with `dotnet tool install dotnet-ef --version <EF version from Directory.Packages.props> --tool-path <scratchpad>`, then run `<scratchpad>/dotnet-ef migrations add <Name> --context <Ctx>` from the project folder.
- **New service in the teststack:** besides AppHost wiring, add a port constant in `src/eShop.AppHost/TestStack.cs`, call `WithTestStackService(...)` (`seeded: true` if it has a seeder), and add its database, queue and readiness entry in the teststack configuration (`testing/teststack.json`).
- **Deviations example:** requesting a new scope in the WebApp is a small change you may make to satisfy an acceptance criterion; record it.
- **Tests are not yours:** that includes test projects, Playwright specs and `testing/flows/*.md` entries.

### Planning subtasks (headless PLAN)

Choose `self` when the story touches one service. Shared files that go in the subtask that needs them first: `Directory.Packages.props`, AppHost wiring (`src/eShop.AppHost`), Identity config (`src/Identity.API/Configuration/Config.cs`).

### Checks before you commit

```bash
dotnet build eShop.Web.slnf
dotnet test --project tests/<Service>.UnitTests   # Microsoft.Testing.Platform syntax; each existing unit test project for a service you touched
```

- If you changed `src/eShop.AppHost`, also run `factory teststack publish` and commit the regenerated `deploy/teststack` files, or CI's drift check fails.
- Don't run functional tests, `factory teststack up/load` or Playwright.
- Lint: `npm run lint` (ESLint, `dotnet format --verify-no-changes`, markdownlint); `npm run lint:fix` auto-fixes most.

Scenario data the flow needs, for `test-automation`: users, catalog items, promotions.
